# Обоснование решений по мониторингу, логированию и оповещению

## Выбранные метрики для мониторинга

### Системные метрики
- **CPU Usage** - отслеживание загрузки процессора
- **Memory Usage** - использование памяти JVM

### Метрики Spring Batch
- **batch.items.processed** - количество обработанных элементов
- **batch.job.completed** - количество успешно завершенных заданий
- **batch.job.failed** - количество провалившихся заданий
- **spring_batch_job_duration_seconds** - длительность выполнения заданий

### Метрики приложения
- **http_server_requests_seconds_count** - количество HTTP запросов

**Обоснование:** Эти метрики позволяют отслеживать производительность batch-обработки, выявлять проблемы и планировать масштабирование.

## Выбор способа отправки метрик

**Выбрано: Spring Boot Actuator + Micrometer + Prometheus**

**Причины:**
1. Встроенная интеграция с Spring Boot
2. Micrometer предоставляет стандартизированный API для метрик
3. Prometheus - популярное решение для сбора метрик
4. Минимальные изменения в коде приложения
5. Автоматический экспорт стандартных метрик JVM и Spring

## Выбор способа отправки логов

**Выбрано: Logback + Logstash Encoder + Filebeat + ELK**

**Причины:**
1. Logback - стандартный логгер Spring Boot
2. Logstash Encoder форматирует логи в JSON для удобной обработки
3. Filebeat собирает логи из Docker контейнеров без нагрузки на приложение
4. ELK стек обеспечивает централизованное хранение и поиск логов
5. Kibana предоставляет удобный UI для анализа логов

**Альтернативы:**
- **Fluentd** - более тяжелое решение
- **Прямая отправка в Elasticsearch** - увеличивает нагрузку на приложение
- **Syslog** - менее гибкое решение

## Конфигурация оповещений

**Выбрано: Grafana Alerting**

**Причины:**
1. Интеграция с Grafana дашбордами
2. Простая настройка правил оповещений
3. Визуализация состояния оповещений
4. Возможность интеграции с различными каналами уведомлений

**Настроенные оповещения (через UI Grafana):**
1. **Batch Job Failed** - критическое оповещение при провале задания
   - Запрос: `batch_job_failed_total{job="batch-processing"} > 0`
   - Условие: Alerting при значении > 0
   
2. **High CPU Usage** - предупреждение при загрузке CPU выше 80%
   - Запрос: `process_cpu_usage{job="batch-processing"} * 100 > 80`
   - Условие: Alerting при значении > 80 в течение 1 минуты

**Инструкция по настройке:**
1. Откройте Grafana (http://localhost:3000)
2. Перейдите в Alerting → Alert rules
3. Создайте новое правило с указанными выше запросами

**Обоснование:** Эти оповещения позволяют быстро реагировать на критические проблемы в работе batch-обработки.
